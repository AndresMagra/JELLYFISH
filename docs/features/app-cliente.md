## Textos legales: qué falta para publicarlos

1. **Completa `packages/shared/src/business.ts`**: razón social, RNC, dirección, teléfono y correo de soporte vienen como `[por definir]` (no se inventó nada). En la app esos marcadores salen resaltados para que se vean.
2. **Pásalos por un abogado.** Los cuatro textos (términos, privacidad, devoluciones y cadena de frío) son un borrador honesto: la política de privacidad se basa en los principios de la Ley 172-13, **no afirma cumplimiento**. Decisiones de negocio que propone el borrador y que debe confirmar el dueño: reportar problemas dentro de 24 h con foto, no aceptar cambios de opinión sobre producto congelado entregado en buen estado, y que un pedido solo se cancela desde la app mientras esté "Esperando pago" o "Confirmado".
3. **Apaga la franja** "Borrador pendiente de revisión legal" poniendo `LEGAL_DRAFT = false` en `packages/shared/src/legal/es-DO.ts`, y actualiza `LEGAL_UPDATED_AT` cada vez que cambies un texto.

Los textos son plantillas con `{negocio}`, `{razonSocial}`, `{rnc}`, `{direccion}`, `{telefono}` y `{correo}`. La prueba `packages/shared/test/legal.test.ts` revisa que existan los cuatro documentos con sus secciones, que todo marcador esté declarado, que no queden `TODO`/`XXX`/corchetes olvidados y que `[por definir]` solo venga de `BUSINESS`.

## Cómo probarlo

```bash
npx vitest run packages/mobile-core packages/shared     # lógica pura y textos legales
npm run typecheck -w @jellyfish/customer
npm run typecheck -w @jellyfish/mobile-core
```

A mano: levanta el API en modo demo (ver README), exporta la app a web (`npx expo export --platform web`) y recorre favoritos, legales, dirección con ubicación (Chromium con `setGeolocation`), checkout con cupón, pedido con PIN y, desde el panel o la API, pasa el pedido a "en camino" y manda la posición del repartidor (`POST /v1/driver/location`) para ver el seguimiento.

## Límites conocidos

- **No se probó en iPhone ni Android reales**: permisos nativos de ubicación y notificaciones, `expo-clipboard`, Apple Maps/Google Maps desde el teléfono, hápticos y los `Modal` de las hojas sobre pantallas modales de iOS. Se recorrió todo en Chromium (web) contra el API real.
- **Push**: en web, simuladores y builds sin `EAS_PROJECT_ID` no se registra nada. El registro, la baja y el toque en la notificación solo tienen pruebas de lógica (`packages/mobile-core/test/push-core.test.ts`), no se vieron en un teléfono.
- **Seguimiento por consulta repetida (15 s)**, no en tiempo real; si la última posición tiene más de 3 minutos el API responde `stale` y la app lo explica.
- Las fotos del CDN estaban bloqueadas en el entorno de desarrollo: en el recorrido se simularon con imágenes locales (el código usa las URLs https reales).
- Los favoritos y el carrito viven solo en el teléfono (no hay sincronización con la cuenta).
- Pedir de nuevo toma el catálogo con `GET /v1/products` (100 por página, pagina hasta 10 veces). Una línea cuyo artículo ya no sale en ese catálogo se trata como "sin existencia".
